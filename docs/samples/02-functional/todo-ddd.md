# ToDoアプリ（DDD）

## 目的

- 関数型とDDDの考え方を、小さなToDoアプリで見せる。
  - 状態ごとに型を分ける
  - 外部からの入力は境界でバリデーションする
  - ワークフロー関数の入出力に型を付ける
  - イミュータブルにする
- アプリを実際に動かしてデモする。ただし、コンパイル時の警告の実演はしない。

## ファイル

`samples/02-functional/todo-ddd/todo.lisp` に置く。他言語版は作らない。

## ドメインモデル

- ToDoは状態ごとに別の型にする。
  - 未完了のToDo：IDとタイトルを持つ。
  - 完了済みのToDo：IDとタイトルを持つ。
- タイトルは、バリデーション済みの値だけを表す型にする。
  - 1文字以上50文字以下の文字列とする。
- すべての型は作成後に変更できない（読み取り専用）。

## ワークフロー

どの関数も入力と出力の型を宣言する。

- **作成**：外部から来た文字列を受け取り、未完了のToDoを返す。
  - ここ（境界）でタイトルをバリデーションし、条件を満たさなければエラーにする。
  - 以降の関数は、タイトルが正しいことを前提にでき、再チェックしない。
- **完了**：未完了のToDoを受け取り、完了済みのToDoを返す。
  - 完了済みのToDoは受け取れない。二重に完了することを、型で防ぐ。
  - 元の未完了のToDoは変更せず、新しい完了済みのToDoを作る。

## デモの流れ

1. タイトルを2つ渡して、未完了のToDoを2つ作る。
2. 片方を完了にして、完了済みのToDoを作る。
3. 未完了と完了済みのToDoを、それぞれ一覧表示する。
4. 不正なタイトル（空文字、51文字以上）を渡し、境界で拒否されることを示す。

## Lisp版の方針

- 型は `defstruct` で定義し、関数の型は `declaim` の `ftype` で宣言する。
- このサンプルは、型付けを使う箇所の一つとする（もう一つは `fib-typed.lisp`）。
- エラーは、通常のエラー（条件）を発生させて表すだけにする。
- 一覧の絞り込みや変換は、`pipeline.lisp` と同じ高階関数で書く。
- ループと破壊的変更は使わない。
- コンパイル時の型警告の実演はしない。
- 永続化（ファイルやDB）、ID採番の仕組み、UIは扱わない。IDは呼び出し側が渡す整数とする。

## 補足（スライドで口頭）

- より厳密な静的型付けの選択肢として、Coaltonがある。まだ1.0に達していない。
- Coaltonの `Result` 型を使うと、エラーをモナド的に書ける。
- サンプルコードは作らない。

## 実行

- `make todo` で実行し、デモの流れの出力を表示する。
