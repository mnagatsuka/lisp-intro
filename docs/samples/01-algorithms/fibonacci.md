# フィボナッチ

## 目的

- `(time (fib 35))` で、Lispがコンパイルされた言語として十分に速いことを見せる。
- Lispは型宣言なしと型宣言ありの2パターンを用意し、型宣言で速度がどう変わるかも見せる。
- Java、Python、Cと速度を比較する。コードの読みやすさは比べない。

## ファイル

`samples/01-algorithms/fibonacci/` に置く。

- `fib.lisp`：型宣言なし
- `fib-typed.lisp`：型宣言あり
- `Fib.java`
- `fib.py`
- `fib.c`

## 仕様

- アルゴリズムはすべての言語で同じ、定義どおりの二重再帰にする。`fib(n)` は `n < 2` なら `n`、それ以外は `fib(n-1) + fib(n-2)` とする。
- メモ化、ループへの書き換え、末尾再帰化はしない。
- `n` は35とし、結果は 9227465 になる。
- 各プログラムは、`fib(35)` の結果と実行時間（秒）を表示する。結果を表示するのは、計算が最適化で省かれないようにするためでもある。
- 実行時間は各プログラムの内部で、`fib(35)` の呼び出し部分だけを計測する。起動やコンパイルの時間は含めない。

## Lisp版の方針

- `fib.lisp`：型宣言なし。`defun` と `(time (fib 35))` だけで書く。
- `fib-typed.lisp`：`fib.lisp` に型宣言（引数と戻り値を整数型に絞る）と、速度優先の最適化指定だけを足す。アルゴリズムは変えない。
- 2つの差分が小さいことが見えるようにする。
- コンパイルして実行する（SBCLのネイティブコンパイル）。
- `time` の出力にはメモリ割り当てなども含まれるが、見せるのは主に実行時間とする。

## 他言語版の方針

- Java：`System.nanoTime()` で計測する。JITのウォームアップは含めたまま、特別な対策はしない。
- Python：`time.perf_counter()` で計測する。標準のCPythonを使い、PyPyなどは使わない。
- C：`gcc -O2` でコンパイルし、`clock_gettime` で計測する。
- 各言語の標準的な書き方で、特別なチューニングはしない。

## 比較の方針

- 実行環境の方針（同じDocker VM、ネイティブarm64、バージョン固定）は [README](../README.md) に従う。
- 計測は1回ずつとし、4言語を同じ条件で順に実行して結果を並べる。
- 数字の厳密さより、桁の違いが伝わることを重視する。

## 実行

- `make fib` で4言語（Lispは2パターン）を順に実行し、結果と実行時間を並べて表示する。
