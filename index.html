Core idea

  • Lisp is a family of languages (Common Lisp, Scheme, Clojure, Emacs Lisp), not one language.
  • Everything is an S-expression: a list written (operator arg1 arg2 ...).
    • e.g. (+ 1 (* 2 3)), with the same syntax for code and data.
  • Code is data (homoiconicity).
    • A program is a list that the program itself can build and manipulate.
    • This makes macros possible: code that writes code.
  • Tiny core, built up by abstraction.
    • A few primitives plus lambda are enough to build the rest.
    • An evaluator for Lisp can be written in Lisp itself in a page or two (the idea behind SICP's metacircular evaluator).

Short history

  • 1958 John McCarthy (MIT) starts Lisp for AI research. The name comes from "LISt Processing". It is the second-oldest high-level language still in use, after Fortran.
  • ~1960 Steve Russell implements McCarthy's eval on the IBM 704. The theory becomes a working interpreter; the Lisp 1.5 manual follows in 1962.
  • 1970s–80s Lisp dominates AI research (MacLisp, Interlisp, Lisp machines). The late-1980s AI winter hits it hard.
  • 1975 Scheme by Sussman and Steele (MIT): a minimal design with lexical scope, later the language of SICP.
  • 1984–94 Common Lisp consolidates the dialects; ANSI standard in 1994.
  • 1980s GNU Emacs, with Emacs Lisp as its extension language.
  • 2007 Clojure by Rich Hickey brings a modern Lisp to the JVM.
  • Today Not mainstream, but alive and influential.
    • Still maintained: SBCL, Clojure, Racket, Guile, Emacs Lisp.
    • Its ideas spread widely: garbage collection, first-class functions, lambdas, the REPL, dynamic typing.
    • JavaScript started as an attempt to put Scheme in the browser (Brendan Eich). See A Brief History of JavaScript.
    • Real-world examples: Nubank (Clojure), Grammarly's grammar engine (Common Lisp), Viaweb (Lisp).

2. Why it's elegant

Simple and small, yet endlessly expressive. You can grow the language toward your problem.

1. Uniform syntax

  • Only one form: (operator arg ...). No operator precedence, no special cases.
  • Parentheses make the structure of the program explicit (a tree).
(if (> x 0) "pos" "non-pos")   ; same shape as a function call

2. Code is data

  • A program is a list, so programs can inspect and build other programs.
'(+ 1 2)         ; just a list of three items
(eval '(+ 1 2))  ; => 3

3. Macros: extend the language itself

  • A macro rewrites code before it runs, so you can add new syntax.
  • In most languages, new syntax needs a language update.
(defmacro unless (test &body body)
  `(if ,test nil (progn ,@body)))

4. Functions as values and closures

  • Functions can be passed, returned, and stored like any value.
  • Closures capture their environment: enough to build objects, counters, and streams.
(map (lambda (x) (* x x)) '(1 2 3))  ; => (1 4 9)

5. Interactive development with the REPL

  • Write, run, and change code in a live running program. No restart cycle.
  • Same style as Emacs customization, where the running editor is edited from inside.

3. Lisp today

Classic AI

  • Main language of symbolic AI: expert systems, planning, natural language (e.g. SHRDLU).
  • Symbols and lists map naturally to knowledge and rules.
  • Cyc, a long-running common-sense knowledge base project, grew out of this tradition.
  • Fell out of fashion with the AI winter and the rise of statistical and neural methods.
  • Worth revisiting: symbolic reasoning is coming back as a complement to LLMs.

Tools

  • Emacs: Emacs Lisp lets users rewrite the editor while it runs. Org-mode and Magit are built on it.
  • CAD: AutoCAD embeds AutoLISP for scripting drawings. A good fit, since drawings are nested data.

Systems

  • Real products still run on Lisp, mostly in niches where expressiveness matters.
  • Clojure at Nubank (digital bank) on the JVM.
  • Common Lisp at Grammarly (grammar engine) and ITA Software (flight search, later Google Flights).
  • Quilc, the compiler for Rigetti's quantum computers, is written in Common Lisp.
